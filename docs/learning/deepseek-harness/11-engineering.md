# 11. 工程化：从学习插件到可交付插件

本页是开发参考，不是已执行的发布教程。提供检查顺序、设计约束和官方操作入口；本知识库没有发布或安装自定义 bundle。

## 先定义最小可交付需求

写清可观察结果，例如“模型能够查询一个由配置选定的知识源，返回稳定字段，查询失败能诊断，取消后停止 I/O”。再写接受与拒绝条件。用这份说明选择扩展点和测试，不要先复制整个包结构。

部署会变化的选择放进 validated Config，例如端点、路径、超时和资源上限。协议固定值与不变的安全条件不必变成配置。配置能自我判断是否错误时，应在加载时明确失败；需要服务或资源才能判断时，在最早可确定的位置失败。

## 源码插件、bundle 与库

本地源码插件可以用一次 patch 插入模块进行开发。可安装分发需要 `package.json` 的 `dsh.bundle.patch`、配置层及构建的 ESM 文件，用户把 bundle 安装到 profile 后才激活其层。没有 bundle 声明的依赖，不会因此自动变成启用的插件。

构建要确保正式 exports 指向真实产物，patch 能解析插件模块；不能把只有当前源码 paths 才能解析的结果当作 npm 包验证。链接安装、普通安装、源码运行和 Desktop 载体都有自己的解析条件，peer 共享和版本兼容按项目规则处理。

操作入口：[打包与安装](../../user/develop/basic/publish.zh.md)、[包检查清单](../../cookbook/adding-a-package.zh.md)、[CLI 行为](../../../apps/cli/reference/README.zh.md)。这些步骤应在实际选择分发方案后执行并记录结果。

## 验证必须覆盖真实责任

| 验证层 | 说明什么 | 不能替代什么 |
|---|---|---|
| 类型检查 | 当前接口与静态推导可用 | JSON 输入有效、业务正确 |
| 业务与边界验证 | 数据与错误按定义处理 | 加载接线与生命周期 |
| 真实 Cordis/Loader 组合 | inject、Config、effects、scope 的接线 | 真实模型选择行为 |
| 无密钥 loop/snapshot | 已指定模型响应下的日志、提示与结果 | 提供方实际 HTTP 协议与缓存 |
| built 安装/启动 smoke | 产物与正式模块解析可用 | 长期稳定性与平台矩阵 |
| 真实 API 或浏览器集成 | 模型协议、真实交互与呈现 | 所有异常与平台路径 |

根据变化选择这些层。修改输入/输出或产品行为时，维护拥有其模型体验的 recorded-session snapshot；SDK 投影或 Session 类型变化还需同时核对 TS/Python 相关输出。小型个人学习文件不等同于向仓库贡献一个完整能力包。

## 常见失败怎样定位

| 症状 | 先核实 |
|---|---|
| apply 没运行 | 模块解析、disabled、必需服务、fiber 状态 |
| 工具看不见 | scope、preset revision、restrict、所用模式 |
| 工具可以看到但不能调用 | 参数、审批/guard、执行身份与取消 |
| 改配置却还是旧行为 | 更高层 patch、整块覆盖、HMR、已有 preset revision |
| 暂时成功但重启丢状态 | 是否只有闭包状态，是否有持久事件与提供方 |
| 测试成功但安装失败 | exports、built 文件、bundle 声明与 peer 版本 |
| 卸载后还有活动 | 原生资源是否有 effect，是否等待工作停稳 |

## 持久事件的额外责任

`SessionEventMap` 是可合并的类型表，未知必读事件会影响读取器。运行时数据需要 owning schema/生成信息，不可只添加 TS 声明。区分业务事件的新增与结构性 Session 格式变化；后者涉及相邻迁移，已发布代不能被覆盖。详细流程以[持久类型审查](../../cookbook/reviewing-persistence-type-changes.zh.md)为准。

## 主目标 B 的验收

独立插件应做到：能解释需求与所选扩展点的关系；Consumer 不依赖具体提供方；schema 与规范返回对应；必要 I/O 支持取消；注册和资源卸载干净；能力属于正确 scope；数据寿命明确；在实际加载路径验证；说明已验证与尚未验证的范围。若需要分发，再完成 bundle 的 built 安装验证。

## 迭代知识库

每次项目版本变化先更新基线与验证记录，再核对服务签名、执行事件、格式和 profile/preset 规则。正式项目文档与源码拥有最新 API，个人知识库保留概念关系和学习记录。不要让学习材料成为第二份无人校验的 API 全量清单。
