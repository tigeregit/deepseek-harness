## 每轮对话的建议节奏

1. 先提出一个系统问题，明确它在全局中的位置。
2. 用你熟悉的 Python/C++ 概念建立联系，指出类比的限制。
3. 解释关键机制与设计取舍，只引入当前必要的 API。
4. 让你预测一个正常或失败场景，再对照源码/实验。
5. 根据回答定位缺失前置概念，最后记录已确认理解与下一步。

不把“听懂讲解”直接判作通过。对理解暂时不确定的部分标记待验证，再通过复述、预测或改动验证。

## 第一轮建议：项目为什么需要 Harness？

可以直接发送：“从第 1 章开始，先解释模型、Harness、Cordis 的责任，再让我用自己的话复述。暂不进入 API 细节。”

这一轮要得到一个可以由你解释的全局图：模型产生动作意图，Harness 管理循环与状态，工具连接实际能力，Session 记录事实，Cordis 组装并管理这些组件。之后再问“如果替换模型后端，哪些职责应该不变”，引入接口与提供方，而不是立即跟读一个大函数。
